# ADR-006：TOFU + 带外安全码核对，不做自动防中间人

- 状态：Accepted
- 日期：2026-09-08（v1.0 开发期）
- 相关：`src/security/fingerprint.ts`、`src/security/e2ee.ts`、[THREAT_MODEL.md](../THREAT_MODEL.md) §4.2/§5.1

## 背景

首次建立会话时必须交换公钥。没有历史信息可用时，协议无法单凭自身判断"这个公钥是不是中间人注入的假公钥"。可选的工程路线：引入中心化信任（如 CA/服务器担保）、或者把判断交给用户。

## 决策

采用 **TOFU（Trust On First Use）+ 带外安全码核对**：

1. 首次收到的对端公钥被接受并固定（TOFU）。
2. 聊天页右上角盾牌显示双方共同指纹（15 位数字 + 7 emoji，见 ADR-005），用户通过**另一条独立渠道**（电话/当面/微信）核对。
3. 核对后**钉住**指纹；此后对端公钥变化自动红色警告。
4. 公钥对以持久化身份存储（v4 起刷新不丢失），TOFU 固定长期有效。

## 后果

- **收益**：无中心化信任依赖；带外核对是安全密码学社区公认的可行缓解；实现简单可靠。
- **代价**：**核对是用户可选行为**——绝大多数用户不做，不核对则首次交换理论上可被中间人透明；若带外渠道本身也被控制，核对形同虚设（威胁模型 §4.2 残余风险）。

## 替代方案

- 中心化身份/公证（CA、Key Transparency）：可自动防首次 MITM，但引入必须信任的第三方，违背 Nymir 无中心信任定位。
- 密钥轮换广播（当前路线图的"可验证密钥轮换"）：解决"换钥如何安全广播"，仍不能解决首次见面问题，属互补而非替代。
