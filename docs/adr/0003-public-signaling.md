# ADR-003：依赖公共信令，定位"非完全去中心化"

- 状态：Accepted
- 日期：2026-09-08（v1.0 开发期）
- 相关：`src/communication/peer.ts`、[README.md](../README.md)「关于『去中心化』的准确说明」、[THREAT_MODEL.md](../THREAT_MODEL.md) §3/§4

## 背景

"去中心化"是易被滥用的词。Nymir 的数据存储与消息传输是本地/P2P，但 Peer 发现必须有一个"找到对方"的机制。现实约束：浏览器无法直接广播，需要信令服务器中转首次握手。

## 决策

Peer 发现与建连依赖公共 MQTT / WebTorrent 信令（Trystero 提供），**明确不承诺完全去中心化**。对外定位统一为：**无业务服务器 + 本地优先 + P2P 通信**。README 专设「⚠️ 关于『去中心化』的准确说明」一节，禁止宣称"完全去中心化"。

## 后果

- **收益**：零服务器成本；换信令通道（mqtt ↔ torrent）即可切换，未来可替换为自建或去中心化信令（如 Nostr/DHT）。
- **代价**：信令侧可观察连接元数据（谁与谁建连、房间存在性）；信令/建连阶段不是 E2EE 通道。此代价在威胁模型 §3/§4/§5.3 中如实列为残余风险。

## 替代方案

- 完全去中心化（DHT/区块链信令）：Peer 发现更难被观察，但浏览器端实现复杂度与依赖风险大幅上升，且 DHT 本身也有元数据泄露问题，不是免费午餐。
- 自建信令：可控但违背零成本/无服务器定位（见 ADR-001）。
