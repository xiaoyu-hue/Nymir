## 1. 产品目标与使用场景

### 产品目标

Nymir（树洞）是一款**基于 P2P 的匿名即时通讯工具**：消息通过 WebRTC 端到端加密直接在用户设备之间传输，数据只存储在自己浏览器的 IndexedDB 中。无账号体系、无业务服务器、无需注册。定位是"无业务服务器 + 本地优先 + P2P 通信"（**不是**完全去中心化——Peer 发现依赖公共 MQTT / WebTorrent 信令）。

### 使用场景

- 想和某人匿名聊天，不想经过任何业务服务器，也不想要账号。
- 聊完即焚：消息可配置为"读一次即销毁 / 定时销毁 / 持久保留"。
- 换设备迁移：通过加密备份导出/导入，在设备间恢复聊天记录与身份。
- 不想被公共聊天工具收集消息内容与元数据。

### 核心原则

1. **本地优先**：消息明文与密钥材料只存在于用户设备，刷新/重启不丢失（持久化身份）。
2. **端到端加密**：会话消息密文传输，中间节点（含公共信令）只能看到密文与签名。
3. **诚实描述边界**：不夸大"去中心化"与"匿名"——TOFU、公共信令、流量混淆等弱点在 README 与威胁模型中如实声明。
4. **零编程基础作者 + AI 辅助开发**：安全关键代码必须可审计、有测试、有文档。

## 2. 核心概念

| 概念 | 说明 |
| --- | --- |
| **房间（Room）** | 一个聊天会话，有 id、名称、创建时间、对端列表（`RoomInfo`）。 |
| **消息（Message）** | 一条聊天消息：id、内容、发送者、时间戳、阅后即焚配置、已读列表、销毁状态；含 `verified`（签名验证结果）与 `decryptFailed`（解密失败标记）字段。 |
| **阅后即焚（Burn）** | 四种模式（`BurnMode`）：`read_once` 读一次即销毁 / `timed` 定时销毁（burnAfter）/ `scheduled` 定时销毁（burnAt）/ `persist` 持久保留。 |
| **E2EE** | X25519 密钥协商 + 每消息 HKDF 派生密钥 + AES-256-GCM；encrypt-then-sign（Ed25519 签密文）。 |
| **安全码（Fingerprint）** | 双方公钥派生的人类可比对指纹：15 位数字 + 7 emoji，通过带外渠道核对以识别中间人（TOFU 缓解）。 |
| **锁屏（Lock）** | 本地加密数据的访问口令：PBKDF2（60 万次迭代）派生密钥 + AES-256-GCM 字段级加密 IndexedDB。 |
| **假名（Pseudonym）** | 会话内身份标识，与设备绑定有限。 |

## 3. 功能规范

### 3.1 聊天（Chat）

- 创建/加入房间，与对端建立 WebRTC P2P 数据通道。
- 发送文本消息；消息走 E2EE 加密通道，签名失败/解密失败在 UI 明确标示（不静默展示）。
- 消息实时双端收发；对端不在线时进入**离线队列**（`communication/offlineQueue.ts`）待重连补发。
- 连接质量监控（`communication/monitor.ts`）通过 ping/pong 心跳维护（仅时间戳，不加密，属已知局限）。

### 3.2 阅后即焚（Burn）

- 发送前选择四种模式之一；`read_once` 被对方阅读后自动销毁（含双方视图）；`timed`/`scheduled` 按时间销毁；`persist` 长期保留。
- 销毁在本地 IndexedDB 与对方设备执行（协议层尽力，无法防截图/复制）。

### 3.3 安全码核对（Safety Check）

- 聊天页右上角盾牌显示双方共同指纹（15 位数字 + 7 emoji）。
- 用户通过带外渠道核对；核对后**钉住**指纹，公钥变更自动红色警告。
- 未核对的首次交换受 TOFU 弱点影响（威胁模型 §4.2）。

### 3.4 锁屏与本地加密

- 首次使用设置锁屏密码（建议 ≥10 位）；输入密码后解锁会话，超时自动锁定并清理密码材料（`security/manager.ts`）。
- 本地 IndexedDB 字段级加密（v4 格式：per-install 随机盐 + 会话级派生密钥缓存），兼容 v1/v2/v3 旧数据解密。
- 忘记密码 = 本地数据永久不可解密（设计选择）。

### 3.5 备份与恢复

- `persistence/backup.ts`：加密备份（AES-256-GCM，备份文件自带随机盐），导出 JSON；导入恢复需同一锁屏密码。
- 换设备可迁移聊天记录与身份。

### 3.6 多语言（i18n）

- 中文（默认）/ English 双语界面（`src/i18n/`，zh.ts / en.ts）。

### 3.7 其他

- PWA：可安装、离线可用（vite-plugin-pwa）。
- 安装提示（InstallPrompt）、错误边界（ErrorBoundary）与降级 UI。
- 星空背景（Starfield）等视觉组件，液态玻璃卡片风格。

## 4. 数据与存储

- **主存储**：IndexedDB（`persistence/db.ts`，idb 封装），字段级加密。
- **敏感键**：localStorage 中敏感键仅 `removeItem` 删除（无覆写，浏览器不保证物理擦除——见威胁模型 §5.2）。
- **数据模型**：`RoomInfo` / `Message` / `BurnConfig`（见 `src/core/types.ts`），消息含 `verified` / `decryptFailed` / `destroyed` 状态位。

## 5. 安全边界（与威胁模型对齐）

**承诺**（有实现与测试支撑）：
- 会话消息 E2EE（X25519 + 每消息 HKDF + AES-256-GCM）
- 密文签名（encrypt-then-sign）与验签失败可见
- 本地存储字段级加密（PBKDF2-600k + AES-256-GCM，v4 per-install 盐）
- 私钥 `extractable: false`（XSS 无法直接导出原始私钥）
- 带外安全码核对（15 位数字 + 7 emoji，钉住 + 换钥警告）

**不承诺 / 已知局限**（不得在文档或宣传中声称防护）：
- 对抗国家级流量分析与长期元数据关联
- 防止对端截图/复制/二次转发
- 完全去中心化 Peer 发现（依赖公共信令；信令/建连阶段非 E2EE 通道）
- 物理安全的抗取证擦除
- 自动密钥轮换（当前关闭，仍有每消息 HKDF）

完整威胁边界见 [THREAT_MODEL.md](./THREAT_MODEL.md)。

## 6. 明确不做 / 后续考虑

- 服务端离线收件箱（无云端存储）。
- 多设备实时同步（当前仅备份导出/导入迁移）。
- 账号体系、注册、用户名搜索。
- 消息搜索（路线图）、语音消息（路线图）、可验证密钥轮换（路线图）。
- 降低对公共信令依赖（路线图）。
- 不做"宣称完全匿名/完全去中心化"的营销表述。

## 7. 验收标准（可实际检查）

1. 两个浏览器（可不同设备）加入同一房间，可实时互发消息；刷新后身份不变、历史消息可读。
2. 发送 `read_once` 消息，对方阅读后双方视图均自动销毁；`timed`/`scheduled` 按设定时间销毁；`persist` 不销毁。
3. 聊天页盾牌显示 15 位数字 + 7 emoji 指纹；核对后钉住；对端公钥变化触发红色警告。
4. 设置锁屏密码后刷新页面需密码解锁；错误密码拒绝；忘记密码无法恢复（提示明确）。
5. 导出加密备份 → 换浏览器/设备导入 → 聊天记录与身份恢复（需同一锁屏密码）。
6. 篡改/伪造消息（测试注入）导致验签失败时，UI 明确标示失败，不静默展示。
7. 断线后发送消息进入离线队列，重连后自动补发。
8. 中/英文界面可切换，无缺字/漏译。
9. 工程验收：`npm run typecheck`、`npm run lint`、`npm test`（264 项）均通过。
10. 安全相关改动不得突破 [THREAT_MODEL.md](./THREAT_MODEL.md) 声明的信任边界。
