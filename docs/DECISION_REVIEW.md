# 决策审查清单（DECISION REVIEW）

> 本文件是项目的**决策前审查工具**，与 ADR 体系配套：
> **ADR 记录"已经做了什么决定"；本文件负责"做决定之前"的反问。**
> 任何 AI Agent 与作者本人在执行不可逆、花钱、对外发布、影响项目走向的操作前，都必须先过一遍本清单。

---

## 一、什么时候必须走这个流程

出现以下任一情况，**先回答清单再动手**，等作者拍板：

| 类别 | 例子 |
|------|------|
| 不可逆操作 | 删除/覆盖代码、删除分支、强制推送、改写 git 历史、清空数据 |
| 花钱的操作 | 购买服务、付费 API、升级订阅、云资源、第三方审计 |
| 对外发布 | 发布 Release、打 tag、公开发文、部署线上、对外公开仓库 |
| 影响项目走向 | 架构变更、技术选型、版本号策略、停用/移除既有功能、数据迁移 |

## 二、决策三问（必答，缺一不可）

### 1. 坏处 / 代价是什么？
- 这个方案有什么缺点、成本、风险？
- 对现有功能、数据、性能、维护成本分别有什么影响？
- 回答方**不得轻描淡写或只讲好处**；被追问时必须补齐。

### 2. 不做的后果是什么？
- 如果不做或推迟做，会失去什么？
- 损失是永久的还是可逆的？有多大？
- 如果"不做也没损失"，说明这个方案可能根本不必要。

### 3. 什么情况下会后悔这个决定？
- 哪个前提条件不成立时，这个决定就是错的？
- 多久之后还能反悔？反悔的成本多大？
- 有没有"先做小规模试点，再决定要不要全做"的空间？

## 三、五层追问（决策三问不够时用）

### 第一层：目标与范围
- 我们到底要解决什么问题？（用一句话说清）
- 这个改动的最小范围是什么？能不能再小？
- 有没有被顺带改掉、但和本目标无关的东西？

### 第二层：不可逆性评估
- 做了之后能不能撤销？撤销要几步？
- 如果失败，最坏情况是什么？数据会丢吗？用户会受影响吗？
- 有没有办法先做"可回滚版本"再上正式版？

### 第三层：替代方案
- 至少列出 1 个替代方案，说明为什么不用它。
- 有没有"更简单/更便宜/更快"的做法？
- 替代方案被否掉的理由是真实约束，还是"习惯"？

### 第四层：时间维度
- 这个决定现在做和一个月后做，差别大吗？
- 有没有正在变化的因素（依赖、平台、政策）会影响这个决定？
- 做完之后多久需要复审？

### 第五层：安全与隐私
- 涉及用户数据、密码、密钥吗？默认提醒风险。
- 有没有把敏感信息写进代码、日志、文档？
- 文档声明的能力，代码里是否真有对应实现？

## 四、常见"反悔场景"速查

| 决定类型 | 典型后悔条件 | 反悔成本 |
|----------|------------|---------|
| 引入新依赖/框架 | 项目后面发现不需要该能力 | 中（迁移成本） |
| 删除旧代码/旧功能 | 有用户/数据依赖它 | 高（可能无法恢复） |
| 花钱买服务 | 使用频率远低于预期 | 低-中（按周期） |
| 发版/打 tag | 版本号语义错误、内容不完整 | 低（可补发） |
| 架构重构 | 测试回归、数据迁移异常 | 高（需回滚预案） |
| 对外公开 | 涉及隐私/合规问题 | 极高（公开即扩散） |

## 五、拍板记录模板

执行前由 Agent 填写，随 PR/提交一起留存：

```markdown
## 决策记录（DECISION LOG）

- **日期**：YYYY-MM-DD
- **决策人**：作者（最终拍板） / Agent（建议）
- **要做什么**：（一句话）
- **触发类别**：□不可逆 □花钱 □对外发布 □影响走向

### 决策三问
1. 坏处/代价：
2. 不做的后果：
3. 后悔条件（何时反悔、成本）：

### 替代方案
- 方案 B：（描述）
- 为什么不用 B：

### 安全/隐私影响
- （有则说明，无则写"无"）

### 拍板结论
- □ 做（作者确认）  □ 不做  □ 先试点/推迟
- 作者确认时间：YYYY-MM-DD
```

## 六、和现有体系的关系

- **AGENTS.md**：把本清单的核心（决策三问）写成了 AI 必须遵守的规则——AI 进入仓库自动加载。
- **ADR**：决定做完之后，把"为什么这么做"沉淀为 ADR 记录，供将来回顾。
- **CHANGELOG**：用户可见的变更记入 CHANGELOG，保持"文档与代码同步"。

> 一句话：**小事直接做，大事先三问，问完拍板写下来。**
