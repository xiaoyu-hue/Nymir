# Nymir 威胁模型（Threat Model）

> 版本：1.0  
> 日期：2026-09-08  
> 状态：基于当前 master 实现整理  
> 原则：诚实描述能力边界，不夸大安全性。

本文档定义 Nymir 保护什么、假设什么、防什么、不防什么。  
任何涉及加密、密钥、信令、存储的改动，应对照本文档评估是否改变威胁边界。

---

## 1. 目标与范围

Nymir 是**本地优先 + P2P 直连**的匿名即时通讯工具。

**在范围内（In Scope）**

- 浏览器端运行的 Web 应用
- 消息内容的端到端机密性与完整性（在已建立的 peer 会话中）
- 本地加密数据（IndexedDB + 锁屏密码保护）
- 阅后即焚配置行为
- 签名失败时的可见提示（不静默展示）

**明确不在范围内（Out of Scope）**

- 对抗国家级流量分析与长期元数据关联
- 防止对方截图、复制、录屏或二次转发
- 完全去中心化的 Peer 发现（仍依赖信令服务器建连，但节点现已支持用户自托管 / 自定义，见 ADR-0009）
- 服务端离线收件箱、多设备实时同步
- 物理安全的“抗取证擦除”（浏览器不保证磁盘覆写）
- 操作系统 / 浏览器本身的漏洞

## 2. 资产（Assets）

按敏感度大致排序：

| 资产 | 说明 | 敏感度 |
|------|------|--------|
| 消息明文 | 用户发送的聊天内容 | 极高 |
| 端到端私钥（X25519 / Ed25519） | WebCrypto 中不可导出私钥 | 极高 |
| 锁屏密码 / 派生密钥 | 用于加密本地数据 | 极高 |
| 本地加密数据库内容 | IndexedDB 中的消息与房间数据 | 高 |
| 签名验证结果 | 消息是否通过 Ed25519 验证 | 高 |
| 假名 / Peer 标识 | 会话内身份标识 | 中 |
| 连接元数据 | 谁与谁建立了连接、时间、信令侧可见信息 | 中 |
| 流量模式 | 消息大小、间隔、噪声填充模式 | 中低 |

## 3. 攻击者与能力假设

| 攻击者 | 能力 | 典型目标 |
|--------|------|----------|
| **被动网络窃听者** | 观察流量，无法主动注入 | 推断谁在通信、消息是否存在 |
| **公共信令服务器** | 观察 MQTT/WebTorrent/Nostr 发现过程中的连接元数据 | 关联 Peer、房间存在性（现支持改用自托管 / 可信节点，见 ADR-0009） |
| **首次交换中间人（MITM）** | 在首次公钥交换时注入假公钥（TOFU 攻击） | 解密后续消息 |
| **XSS / 恶意脚本** | 在应用同源下执行代码 | 读取内存中的密码缓存、已解密消息 |
| **物理接触设备的人** | 能打开浏览器、做磁盘取证 | 恢复 localStorage / IndexedDB 残留 |
| **积极流量分析者** | 统计消息大小、间隔、噪声模式 | 识别 Nymir 流量特征 |
| **恶意对端用户** | 正常参与会话的一方 | 截图、复制、长期保留消息 |

**不假设的攻击者能力（当前不承诺防护）**

- 能破解现代 WebCrypto 原语（AES-256-GCM、X25519、Ed25519、PBKDF2-600k）
- 能在不触发浏览器安全策略的情况下导出不可导出私钥
- 能绕过浏览器同源与沙箱限制（除非存在浏览器 0-day）

## 4. 信任边界与假设

### 4.1 信任边界

```
[用户设备 / 浏览器]
  ├── WebCrypto（密钥生成、加解密、签名）  ← 信任实现正确
  ├── IndexedDB / localStorage            ← 信任浏览器隔离，不信任物理擦除
  ├── 应用 JS 代码                        ← 同源内视为可执行任意逻辑（XSS 风险）
  └── WebRTC 数据通道                     ← 消息内容在 E2EE 保护下传输

[公共信令：MQTT / WebTorrent]
  └── 仅用于 Peer 发现与建连信令          ← 不信任其机密性与完整性

[对端设备]
  └── 对方浏览器与用户行为                ← 不信任（可截图、可复制）
```

### 4.2 关键安全假设

1. **浏览器 WebCrypto 正确，私钥以加密形式持久化**  
   私钥以 `extractable: true` 生成（为支持刷新后持久化身份需导出），但导出后仍以锁屏密码加密存储于 IndexedDB；XSS 仍可能调用已加载的 CryptoKey 对象，残余风险见第 5.4 / 7 节。

2. **TOFU（Trust On First Use）+ 带外安全码核对**  
   第一次交换的公钥被接受并固定。若首次交换被中间人抢先注入假公钥，后续会话对攻击者透明。  
   **缓解**：聊天页右上角盾牌可显示双方共同的 15 位数字 + 7 个 emoji 指纹；用户需通过另一条独立渠道（电话/当面/微信）与对方比对。核对后钉住指纹，公钥再变会自动弹红色警告。  
   **残余风险**：核对是用户可选行为，绝大多数用户不会做；且若带外渠道本身也被中间人控制，指纹核对形同虚设。

3. **锁屏密码由用户妥善保管**  
   忘记密码 = 本地加密数据永久无法解密（设计选择，非缺陷）。

4. **公共信令不可信**  
   信令侧可能观察连接元数据；建连阶段本身不是端到端加密通道。

5. **消息内容仅在已完成密钥交换的 P2P 通道中受 E2EE 保护**  
   不经过业务云端存储。

6. **阅后即焚是“减少留存”而非“防对方记录”**  
   无法阻止对端截图、复制或录屏。

## 5. 主要威胁与当前缓解

### 5.1 消息内容被窃听 / 篡改

| 威胁 | 缓解措施 | 残余风险 |
|------|----------|----------|
| 网络窃听消息内容 | X25519 ECDH + AES-256-GCM + 每消息 HKDF 派生 | 首次交换若未核对安全码，仍可能被中间人透明 |
| 消息被篡改或伪造 | Ed25519 密文签名（encrypt-then-sign 设计意图）；验签失败在 UI 可见 | 签名公钥同样受 TOFU 影响；同样靠带外安全码核对 |
| 对端私钥泄露 | 私钥导出后以锁屏密码加密存储（extractable: true）；会话根密钥有限缓存；一次性临时密钥会话结束即从内存丢弃 | XSS 仍可能使用已加载的 CryptoKey 对象；长期静态私钥泄露后，仅握手前首个往返（纯静态根窗口）与未启用临时密钥的旧客户端会话可被解密（弱前向保密的边界，见 ADR-0008） |

### 5.2 本地数据泄露

| 威胁 | 缓解措施 | 残余风险 |
|------|----------|----------|
| 设备被他人打开 | 锁屏密码 + 自动锁屏计时；解密需密码 | 密码强度依赖用户；内存中可能有短暂明文缓存 |
| 磁盘取证恢复旧数据 | 敏感键尽量 removeItem；reset 时先写随机再删除 | **浏览器不保证物理覆写**，取证仍可能恢复 |
| 密码错误暴力尝试 | 失败次数限制 + 临时锁定 | 仅客户端限制，可被绕过（清 sessionStorage） |

### 5.3 元数据与流量分析

| 威胁 | 缓解措施 | 残余风险 |
|------|----------|----------|
| 信令侧看到谁连谁 | 消息内容不经信令；信令节点现可自配 / 自托管（ADR-0009），用户可改用可信节点 | 连接关系、房间存在性仍可能被（公共）信令观察；改用自托管节点可消除此风险 |
| Nostr relay 协调元数据 | Nostr 策略下 rendezvous 由 Trystero 经公共 relay 完成，relay 可见协调元数据 | 改用自托管 Nostr relay（ADR-0009）可消除对公共 relay 的依赖；**端到端加密的 rendezvous 需 fork Trystero，当前未实现**（见 ADR-0009 边界） |
| 流量模式识别 | 随机化噪声填充（8–28s 随机间隔、24–512B 随机长度） | 强度有限，认真分析仍可能识别；彻底混淆需远端代理，纯浏览器不可行 |
| 连接监控 ping/pong | 不涉及聊天内容，仅时间戳；间隔已随机化（3.5–7s） | ping 内容未经额外 E2EE（WebRTC DTLS 已加密通道，额外加密收益有限）；周期性节奏已削弱，但 WebRTC 数据通道指纹仍可能被识别 |

### 5.4 应用内攻击（XSS 等）

| 威胁 | 缓解措施 | 残余风险 |
|------|----------|----------|
| 恶意脚本读取密码 / 消息 | 私钥不可导出；密码仅以 Uint8Array 存储，锁定时 fill(0) 清零 | 已解密消息在 JS 堆中短暂存在；无持久密码字符串副本 |
| 恶意脚本滥用 CryptoKey | 同源脚本可调用已导入的密钥对象 | 需依赖 CSP 与依赖供应链安全 |

### 5.5 对端恶意行为

| 威胁 | 缓解措施 | 残余风险 |
|------|----------|----------|
| 对方截图 / 复制 | 阅后即焚减少本地留存 | **无法防止**对方记录 |
| 对方长期保存消息 | 阅后即焚可配置 | 对端设备不在控制范围内 |

## 6. 当前实现中的安全属性（与代码对应）

- **本地加密**：PBKDF2（600k iterations）+ AES-256-GCM，当前格式 v4（per-install 随机盐 + 会话级派生密钥缓存），兼容 v1/v2/v3 旧数据解密
- **会话 E2EE**：X25519 + 每消息 HKDF + AES-256-GCM
- **完整性**：Ed25519 签名；验签失败应在 UI 明确标示
- **私钥保护**：生成时 `extractable: true`（导出后仍以锁屏密码加密存储；XSS 风险见 5.4 节）
- **弱前向保密（Weak Forward Secrecy）**：每次会话叠加一次性临时 X25519 密钥，临时私钥会话结束即从内存丢弃（ADR-0008）；长期静态私钥泄露无法解密已启用临时密钥的历史密文，但仍非“强前向保密”——握手前的首个往返与未启用临时密钥的旧客户端会话仍可能在静态根下被解密
- **锁屏**：内存中持有密码材料；超时自动锁定并清理缓存
- **安全删除**：仅 `removeItem`，无覆写（能力边界已在代码注释与 README 中声明）

以上声明必须以代码与测试为准。文档不得超出实现。

## 7. 残余风险与已知局限（汇总）

1. **TOFU + 安全码核对**：首次公钥交换可通过带外核对识别中间人，但核对是用户可选行为；若带外渠道也被控制则仍被绕过。
2. **公共信令元数据**：发现与建连阶段依赖公共服务，连接关系可能被观察（见阶段 2 改进方向）。
3. **流量混淆仍有限**：噪声间隔与长度已随机化（8–28s 随机、24–512B 随机），ping/pong 间隔也随机化（3.5–7s），但字节总量与统计时序仍可被认真流量分析识别；彻底混淆需远端代理，纯浏览器不可行。
4. **无物理安全删除**：浏览器存储删除不保证磁盘覆写。
5. **XSS 与内存**：同源脚本可触及已解密数据与可用 CryptoKey。
6. **对端不可信**：截图、复制、二次传播无法通过协议阻止。
7. **客户端暴力尝试限制可被绕过**：失败计数存在 sessionStorage。
8. **ping/pong 监控消息不加密**：连接质量监控的 ping/pong 通过 P2P 通道明文发送（仅时间戳），网络观察者可推断在线状态和通信频率。不泄露聊天内容，但泄露元数据。
9. **弱前向保密的边界**：临时密钥仅在新客户端间生效；与未升级的旧客户端互通时自动回退到纯静态根（无前向保密），历史消息在该窗口下仍受静态私钥保护强度约束。且握手完成前的首个往返窗口内消息亦在静态根下。

## 9. 如何使用本文档

1. **改安全相关代码前**：确认是否触及上表中的资产或信任边界。
2. **写测试时**：优先覆盖“威胁 → 缓解措施”对应的行为（加密往返、验签失败、锁定后无法解密、迁移等）。
3. **更新 README / 对外宣传时**：不得声称超出本文档与代码实现的能力。
4. **发现新攻击面时**：先更新本威胁模型，再改实现。
